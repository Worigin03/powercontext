## 2. 一句话介绍

把中文研究问题直接变成英文论文里的可核验证据：本地解析 PDF，写入 seekdb 的向量索引与 IK 全文索引，两路召回后用 RRF 融合，再按句子重排，最终每条结论都绑定论文、页码和原句。

## 3. 要解决的问题

- **读得慢**：一篇 30 页论文真正需要的只有两三段，通读后再定位，时间都花在翻页上。
- **找不准**：中文提问、英文原文，关键词检索对不上；纯向量检索又会召回语义相近但不回答问题的段落。
- **不敢信**：生成式答案流畅但难以核实，科研场景需要能点回原文的证据。

## 4. 核心功能

1. **文献入库**：输入 arXiv ID 自动拉取元数据与 PDF；也支持上传本地 PDF。解析、切块、向量化全部在本机完成。
2. **证据检索**：中文问题跨语言召回英文原文；每条结果展示向量相似度、BM25 与 RRF 融合分，并高亮命中的中英文词。
3. **研究问答**：先把候选块拆成句子重新打分，再按论文去重，输出 3–7 条直接证据，逐条标注 P1/P2 与页码章节；默认不调用大模型，全部使用原文。
4. **跨论文对比**：围绕同一问题并排展示多篇论文的立场与证据，便于写 related work。
5. **综述素材**：按主题生成 Markdown 提纲素材，可下载、复制。
6. **阅读与笔记**：按页阅读原文，左侧章节大纲联动；可对具体页写笔记，笔记写入 seekdb。
7. **文献库管理**：查看主题、年份、页数、块数，按标题检索，一键跳转阅读页或 arXiv。

## 5. seekdb 的实际使用（核心）

### 5.1 数据模型

| 表 | 作用 | 关键字段 |
| --- | --- | --- |
| `papers` | 论文元数据 | `id`、`arxiv_id`、`title`、`authors`、`published`、`topic`、`page_count`、`chunk_count` |
| `chunks` | 证据块（检索核心） | `paper_id`、`page_no`、`section`、`content`、`embedding VECTOR(384)` |
| `glossary` | 中英术语对照 | `zh`、`en` |
| `notes` | 阅读笔记 | `paper_id`、`page_no`、`quote`、`comment` |
| `search_log` | 检索日志与延迟统计 | `query`、`mode`、`latency_ms`、`hits` |

### 5.2 索引

```sql
CREATE TABLE chunks (
  id BIGINT PRIMARY KEY,
  paper_id VARCHAR(32),
  page_no INT,
  section VARCHAR(255),
  content TEXT,
  embedding VECTOR(384),
  FULLTEXT INDEX ft_content (content) WITH PARSER ik,
  VECTOR INDEX vidx_vec (embedding)
    WITH (distance = cosine, type = hnsw, lib = vsag)
);
```

- **向量索引**：`VECTOR(384)` + HNSW（`lib=vsag`），余弦距离。
- **全文索引**：必须显式使用 `WITH PARSER ik`。MySQL 默认分词按空格切分，中文会整段失效；换成 IK 后中英文混排都能命中。
- **选型原因**：同一张表既能做语义召回，又能做中文全文检索和结构化过滤（`paper_id`、`page_no`），不需要再维护独立的向量数据库。

### 5.3 两路召回（实际执行的 SQL）

```sql
-- 向量召回
SELECT id, paper_id, page_no, section, content,
       cosine_distance(embedding, %s) AS dist
FROM chunks
ORDER BY dist LIMIT 30;

-- 全文召回
SELECT id, paper_id, page_no, section, content,
       MATCH(content) AGAINST(%s) AS bm
FROM chunks
WHERE MATCH(content) AGAINST(%s)
ORDER BY bm DESC LIMIT 30;
```

应用层用 RRF（k=60）融合：

```python
rrf += 1.0 / (60 + rank + 1)   # 两路各加一次
```

排序后再做每篇论文最多 2 条的去重，避免单一论文刷屏。

### 5.4 查询扩展与重排

- 115 条中英术语表（如「端侧 → on-device / edge device」「资源约束 → computation / memory / energy」），把中文问题扩展到英文术语，同时用于全文召回与高亮。
- 候选块拆句后重新打分：`0.62 × 向量相似度 + 0.28 × 词面覆盖 + 0.10 × 排名先验`，低于阈值（`max(0.40, 最高分 × 0.70)`）的句子被丢弃；无合格句时回退前 3 条，避免空结果。

## 8. 本地运行

```bash
# 1. 启动 seekdb
docker run -d --name seekdb --restart unless-stopped \
  -p 2881:2881 -v seekdb_data:/var/lib/seekdb \
  oceanbase/seekdb:latest

# 2. 安装依赖
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt

# 3. 建表并写入示例语料（首次会下载嵌入模型，约 90 MB）

```

## 9. 演示脚本（建议 3–5 分钟）

1. **总览**：展示语料规模、主题分布、最近检索与延迟。
2. **证据检索**：输入「RAG 相比纯参数化模型解决了什么问题？」，指出 RAG 论文两条结果同时有向量分与 BM25 分，右侧是 RRF 融合分；高亮中英文命中词。
3. **研究问答**：输入「端侧大模型面临哪些资源约束？」，展示 5 条证据、3 篇文献，逐条标注页码与章节，强调未配置大模型时答案全部来自原文。
4. **跨论文对比**：选择 LoRA 与 RAG，围绕「训练成本与推理开销」对比两篇论文的证据。
5. **文献库 / 阅读页**：按 arXiv ID 入库一篇新论文，等待解析完成；打开阅读页，用章节大纲跳到指定页并写一条笔记。
6. **展示站**：打开 Qoder Sites 站点，说明交互演示是本地 seekdb 的真实返回记录，静态页面不发起实时请求。

## 10. 已知限制

- Qoder Sites 展示站为静态站点，演示数据是录制结果，不能在线发起检索；完整检索需在本地运行工作台。
- 默认不启用大模型，回答是抽取式证据摘要，不做自然语言综述；配置兼容接口后才会生成综述段落。
- 嵌入模型首次运行需要联网下载，之后可离线使用。
- 站点当前为私有访问，如需评委公开访问，需要将访问范围调整为公开。
