# 财报 PDF 全文解析与证据页检索

`powercontext.sources.pdf_pages` 从完整原 PDF 解析全部物理页，并保留既有页级 Source、
标准文本投影和精确 Memory 引用契约。检索只使用已打开 scoped Memory 的公开 API。

## 全文完整性

使用 pypdf 严格读取原始字节，检查页树声明页数与实际页数一致，并核验页面的内容流类型。
缺失页面对象、页数不一致、损坏的内容流数组和非 PDF 文件头统一以 `ValueError` 失败，
不会将自动修复后剩余的页面作为完整报告返回。合法空白页、空内容流及空密码权限文件继续支持。
正文仍使用普通文本提取，保留全部物理页和完整原文件 SHA-256。

## 检索方式

1. 读取一次公开 `Memory.list` 返回的当前 scope 活跃页面记录及其真实 `record.citation`，
   同时执行最多 8 路 `Memory.search` 取得原生排序信号。
   全部活跃 PDF 页面都参与离线重排，避免同词附录挤掉正文报表，或原生词项准入排除同义证据。
2. 规范化财政年份、所有格、常见财务缩写及派生指标。
   例如 R&D 对应 research/development，quick ratio 对应现金、证券、应收账款与流动负债。
   使用页面 BM25、局部词项窗口和原生检索排序信号评分。
3. 根据文档标识匹配主体；问题指定单一财政年份且对应报告存在时，优先该年份报告，
   其他年份保留为补充。正文中提到的未来年份不等于报告年份。
4. 根据问题需要覆盖损益表、现金流量表和资产负债表。标题按完整文字识别，排除带页码的目录条目；
   支持拆行标题、碎片化导航页眉和每个数字单独成行的表格，不依赖同一行包含多个数字。
5. 对同一 PDF 修订的物理相邻续页保留少量位置，使用真实 `Memory.get` 校验最终引用，
   按完整页级 Source 身份去重并遵守返回上限。

每路原生检索上限随调用方 limit 调整，在 `limit=20` 时为 320；这个上限不截断离线页面候选。
页面快照、词频统计与局部窗口计算的工作量随当前 scope 内容规模增加，所有临时状态在问题处理结束后释放。
不保留跨 scope、数据库或 Memory head 的全局结果缓存，不创建与实际 Memory 记录无关的引用。

完整 Source 身份保留 PDF 修订，因此相同文档页码的不同 PDF 修订互不覆盖；
长文档 ID 使用的摘要形式也可正常返回。排序用的词形规范化不会改写解析正文、存储内容或引用。

金融术语映射是通用查询处理，不包含特定公司、财报、问题、数字答案或标注页码。
产品代码不读取 FinanceBench 答案、证据标注、预解析文件或判题资产。

## 验证

- Linux Python 3.12、pypdf 6.19.0：完整 503 页公开验收、6 项 PDF 完整性回归、
  13 项真实 Runtime 检索回归及 12 项 Source 兼容回归，共 37 项通过。
- 完整性回归覆盖缺失页面对象、页树计数、损坏内容流数组、非 PDF 头，
  以及带正文和空白页的普通文件、空密码权限文件。
- 检索回归覆盖长文档摘要身份、修订身份、法律问法、跨公司干扰、目录/综合收益表干扰、
  经营地域、重启后物理续页与 limit、碎片化导航页眉、派生指标、财务缩写、报告年份、
  大量同词附录下的正文召回，以及数字单独成行的报表。
- 四份完整原始财报的 576 页经真实 Runtime 持久化并重启，自拟的研发费用、速动比率、
  流动比率与资产收益率问题均召回所需类别的报表页，引用逐条回查。
  这是自拟问题的报表覆盖诊断，不是 FinanceBench 标注的 Recall@20。
- 使用 PepsiCo、3M、Adobe、Amazon、Amcor 的 2022 年原始 10-K 共 1079 页，
  对产品解析结果与独立 Poppler 提取逐页做词频多重集合对照。
  每页词项数比例为 0.9962–1.0127，最低词项 F1 为 0.9811。
  这是不同提取引擎之间的交叉验证，不是 FinanceBench 标注质量或平台 Recall@20 分数。
- 完整公开 PDF 的 503 页另与 pdfplumber 独立提取对照，最低词项 F1 为 0.9927。
- Ruff 和针对 PDF 模块的 ty 检查通过。

公开验收不验证平台的全部质量门槛。上述检查不读取答案或证据页标注，
不能代替平台对公开组和留出组的标注文本质量与 Recall@20 验收。
