# 财报 PDF 全文解析与证据页检索

`powercontext.sources.pdf_pages` 从完整原 PDF 解析全部物理页，并保留既有页级 Source、
标准文本投影和精确 Memory 引用契约。检索只使用已打开 scoped Memory 的公开 API。

## 全文完整性

校验末尾的完整 `%%EOF` 标记，再用 pypdf 严格读取原始字节。先遍历完整页树，
核对每个分支的后代页数并拒绝重复节点，再按物理顺序提取每页内容。
缺失页面对象、任一分支页数不一致、损坏的内容流数组、非 PDF 文件头和截断的最终修订均以 `ValueError` 失败。
合法空白页、空内容流及空密码权限文件继续支持。
接口同时接受位置参数与 `parse_pdf_document(value=...)` 关键字参数。

每页先取得完整普通文本，再使用 pypdf 布局模式重建词边界，避免坐标变换和字距调整把单词拆开或黏连。
布局模式未提取的 Form XObject 按实际 `Do` 绘制操作补充提取，包含嵌套表单；未使用的资源不会被加入正文。
使用 Unicode 字母与数字的频次多重集合核验内容，重建不完整时保留普通文本。
布局模式将相邻表头黏连时，使用普通提取中缺失的完整词项恢复这些词边界，按词频限制恢复次数。
只压缩排版空白，不改写原文件；全部物理页、空白页及整个原文件 SHA-256 均保留。
双模式提取与必要的表单恢复会增加解析开销，不依赖 OCR、模型、额外解析库或在线服务。

## 检索方式

1. 读取一次公开 `Memory.list` 返回的当前 scope 活跃页面记录及其真实 `record.citation`，
   执行一次有界的 `Memory.search` 取得原生排序信号。
   全部活跃 PDF 页面都参与离线重排，避免同词附录挤掉正文报表，或原生词项准入排除同义证据。
2. 将派生指标拆成独立证据项，每项支持财报常用的多个行名。
   例如自由现金流需要经营活动现金净额和资本支出，两个数值可分别来自不同页面。
   对页面词频、局部词项窗口、相邻词对、标题和含数值的报表行评分。
3. 根据文档标识匹配主体；报告年份仅作为温和的相关性信号。
   为同一公司不同报告及 PDF 修订保留互补报表或相关片段，避免后续报告的比较年度证据被排除。
4. 优先保留每个独立证据项在各相关报告中的高分页面，再按整体相关性补足。
   使用完整标题识别报表，支持拆行标题、碎片化导航页眉和逐个数字换行的表格。
   问题明确指定某张报表时，即使被问项目没有单独列示，也可返回该报表供核对。
5. 对同一 PDF 修订的物理相邻续页保留少量位置，包括以投资、筹资或经营活动标题开头的现金流续页。
   直接返回快照记录的精确版本引用，按完整页级 Source 身份去重。验收逐条用 `Memory.get` 回查。

原生搜索最多返回 64 条用于辅助排序，离线排序覆盖当前 scope 的完整 PDF 页面快照。
页面快照、词频统计与局部窗口计算的工作量随当前 scope 内容规模增加，所有临时状态在问题处理结束后释放。
不保留跨 scope、数据库或 Memory head 的全局结果缓存，不创建与实际 Memory 记录无关的引用。

完整 Source 身份保留 PDF 修订，因此相同文档页码的不同 PDF 修订互不覆盖；
支持摘要形式的长文档 ID，以及经 Memory 去除外侧空白和 Unicode NFC 规范化的文档前缀。
排序用的词形规范化不会改写解析正文、存储内容或引用。

金融术语映射是通用查询处理，不包含特定公司、财报、问题、数字答案或标注页码。
产品代码不读取 FinanceBench 答案、证据标注、预解析文件或判题资产。

## 验证

- 使用锁定依赖、1 CPU 和 2 GiB 内存运行官方 503 页公开验收，以及 PDF 解析、真实 Runtime 检索和 Source 兼容回归。
- 完整性回归覆盖缺失页面对象、页树计数、损坏内容流数组、非 PDF 头，
  以及带正文和空白页的普通文件、空密码权限文件、关键字调用、坐标变换字距断词、Form XObject 正文、
  截断的 EOF 和增量修订、相邻表头词边界，以及根页数正确但子分支页数错误的文件。
- 检索回归覆盖长文档摘要身份、修订身份、法律问法、跨公司干扰、目录/综合收益表干扰、
  经营地域、重启后物理续页与 limit、碎片化导航页眉、派生指标、财务缩写、报告年份、
  大量同词附录下的正文召回、数字单独成行的报表、跨报告比较年度证据、现金流续页、文档 ID 规范化、
  自由现金流的跨页证据，以及报表没有单列问及项目的情况。
- 使用 15 份公开原始完整 10-K 共 2891 页，与独立 Poppler 和 MuPDF 提取逐页做词频多重集合对照，
  每页词项数量均在独立结果的 90%–110% 之间，全部页面词项 F1 不低于 0.95。
  样本涵盖 Apple、Boeing、Coca-Cola、CVS Health、General Mills、Intel、JPMorgan、Microsoft、
  Nike、Walmart、3M、Adobe、Amazon、Amcor 和 PepsiCo。
  这是原始 PDF 提取引擎间的交叉验证。
- 另外将五份原始财报的 1079 页提交到同一 Runtime，重启后用 20 道自拟问题检索。
  新旧版本都在前 20 条找到全部 25 个逐页核对的目标证据，前 3 条命中从 18 个增加到 21 个。
  逐条检查了引用回查、存储正文、原文件摘要和物理页码。
- Ruff 和针对 PDF 模块的 ty 检查通过。

公开验收不验证平台的全部质量门槛。上述检查不读取答案或证据页标注，
不能代替平台对公开组和留出组的标注文本质量与 Recall@20 验收。
