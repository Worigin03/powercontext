HOW IT WORKS

从 PDF 到可核验的引用

整条链路在本机完成：解析、切块、向量化，写入 seekdb 后从两路索引召回，再用 RRF 融合排序。

  1. 01

    解析

    pypdf 按页抽取文本，识别章节标题，修复跨行连字符，跳过参考文献。

  2. 02

    切块

    约 700 字符一块，保留一句重叠，让跨块的论证不断裂。

  3. 03

    向量化

    fastembed 本地运行多语言 MiniLM，384 维，中文问题可以直接匹配英文原文。

  4. 04

    混合召回

    seekdb 分别返回 HNSW 向量候选与 IK 全文候选，应用层用 RRF 融合两路排名。

  5. 05

    重排引用

    把候选块拆成句子重新打分，按论文去重，输出证据与页码。

recall · 2 queriesretrieval.py
-- 向量召回：HNSW + cosine
SELECT id, paper_id, page_no, section, content,
       cosine_distance(embedding, %s) AS dist
FROM chunks
ORDER BY dist LIMIT 30;

-- 全文召回：IK 分词 + BM25
SELECT id, paper_id, page_no, section, content,
       MATCH(content) AGAINST (%s) AS bm
FROM chunks
WHERE MATCH(content) AGAINST (%s)
ORDER BY bm DESC LIMIT 30;

// 应用层融合
rrf += 1 / (60 + rank + 1);
schema · indexesdb.py
CREATE TABLE chunks (
  id BIGINT PRIMARY KEY,
  paper_id VARCHAR(32),
  page_no INT,
  section VARCHAR(255),
  content TEXT,
  embedding VECTOR(384),
  FULLTEXT INDEX ft_content (content)
    WITH PARSER ik,
  VECTOR INDEX vidx_vec (embedding)
    WITH (distance = cosine,
          type = hnsw, lib = vsag)
);

为什么两种召回都要

向量负责跨语言语义：中文「资源约束」能召回英文的 computation / memory / energy。全文负责精确术语：LoRA、RAG、MRR 这类缩写不会被同义改写淹没。两路结果用 RRF（k=60）融合。

为什么不直接让大模型回答

默认不配置大模型，答案完全由检索到的原句组成，避免编造。配置 OpenAI 兼容接口后，模型也只被允许依据给定证据作答，并逐条标注来源。

为什么要按论文去重

相似段落常常来自同一篇论文的相邻页面。限制每篇最多两条证据，问题涉及多篇文献时不会被单一论文刷屏。

POWERED BY SEEKDB

为什么是 seekdb

论文语料同时需要语义召回、中文全文检索和结构化过滤。把三件事放进一个数据库，链路短，延迟也可控。

VECTOR

HNSW + cosine

VECTOR(384) 列与 VECTOR INDEX … lib=vsag 直接建在证据块表上，不必维护额外的向量服务。

FULLTEXT

中文 IK 分词

MySQL 默认分词按空格切分，中文会整段失效。切换到 WITH PARSER ik 后，中英文混排的全文检索都能命中。

HYBRID

两路召回，库内完成

HNSW 与 IK 全文的候选都由 seekdb 返回，应用层只做 RRF 融合，不需要再维护一套独立的向量存储。

OPS

熟悉的运维方式

兼容 MySQL 协议，Docker 单机拉起，pymysql 直接连接。备份、排查、扩表都和日常数据库一致。

RUN IT LOCALLY

在自己机器上跑起来

需要 Python 3.11+ 与 Docker。首次启动会下载约 90 MB 的多语言嵌入模型，之后完全离线可用。

  • seekdb 1.4.0 · Docker · 127.0.0.1:2881
  • FastAPI + pymysql + pypdf + fastembed
  • PDF 解析、切块、向量化均在本地完成
  • 可选：配置 OpenAI 兼容接口启用 LLM 综述

python run.py
